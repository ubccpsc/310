Software isn't just some abstract code: it exists in the real world.
We build software to solve real-world problems, whether that means building a chat application to help people communicate more quickly, or a video-streaming website so all the movies are right at your fingertips.
But how do we actually know what software to build?
Specifically, even if we know the requirements of our software, how do we actually translate to designing and building a real software system?

This unit takes us through the process of transforming abstract, real-world requirements into a concrete software design and specification.
We transform abstract and imprecise real-world requirements into specific scenarios, which inform data requirements and a data model, and finally, a concrete specification that covers the action a user can take and how the data flows.
